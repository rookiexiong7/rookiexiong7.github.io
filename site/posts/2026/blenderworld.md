## 1. Motivation：看起来像三维，不等于真的建好了三维

视觉 Agent 已经能够根据自然语言和参考图调用 Blender、编写 Python、反复渲染并交付一个场景。但在实际创作中，用户需要的通常不只是一张“像”的图片：室内方案要保持家具关系，产品模型要满足尺寸与材质要求，动画要真正发生运动，最终工程还要可编辑、可复用。

这使 3D 创作评测面临一个核心问题：**如何区分从指定相机看起来正确的视觉捷径，与在多个视角下仍成立的三维结构？** 一张渲染图无法可靠检查物体是否有厚度、角色是否接触地面、零件尺寸是否准确、动画和材质节点是否真的存在。开放式设计又往往没有唯一的三维真值，不能简单地把输出与一个标准网格逐点比较。

BlenderWorld 因此不把结果压缩成单张图片，而是要求 Agent 交付可编辑的 `.blend` 工程及指定导出物，再从视觉证据和场景内部状态两侧检查它。作者将其定位为面向真实 3D 创作请求的综合基准，覆盖重建、修改和参考式设计，而不是只考察孤立物体或预先定义的几何操作。

## 2. Insight：评测对象不是一张图，而是一套可被反证的工程

### 2.1 可编辑工程让视角捷径暴露出来

如果只评价提交相机的画面，Agent 可以用贴图平面、单面卡片或针对当前视角调出的几何蒙混过关。BlenderWorld 的评测 Agent 会为每个工程选择八个互补视角，并直接查询场景结构。一个从正面成立、从侧面消失的人物，不再只是“另一张图不好看”，而是三维表示本身缺少体积的证据。

这种设计也改变了基准测量的能力：分数同时包含视觉理解、三维规划、Blender 编程、工具调用、调试和交付可靠性。它更接近完整生产系统的表现，但不能被解释为底层模型纯粹的空间推理分数。

### 2.2 要求满足与视觉质量是两种不同的成功

一个工程可能满足尺寸、数量和交付格式，却有明显穿模、僵硬光照或粗糙造型；另一个工程也可能非常漂亮，却漏掉规格文件中的关键约束。BlenderWorld 因此把任务级二元准则与八项连续质量评分分开，再各占一半合成总分。

在全部 2,899 个模型—任务输出上，两部分分数的 Spearman 相关系数为 0.630：总体正相关，但远没有重合。这支持将“按要求完成”与“整体质量好”视为互补信号，而不是用一个视觉偏好分数替代所有工程检查。

### 2.3 看得更多，不代表更会修

模型可以频繁查看渲染结果，却没有正确诊断缺陷，或者修错了目标。实验中，DeepSeek-V4.1-Flash 平均每题进行 31.3 次图像查看，Seed2.1pro-0915 为 33.9 次；GPT-6-Astra 只有 15.0 次，却取得最高的多模态分数。

这个聚合结果不能证明少看更好，因为模型、harness、token 使用和行动策略都不同。它能支持的较弱结论是：视觉调用次数只表示获得反馈的机会，不能表示反馈被有效转成了结构修正。真正需要衡量的是“发现哪处不对—定位对应场景变量—实施修复—重新验证”的闭环质量。

## 3. Method：从生产简报到结构—视觉双通道评分

### 3.1 223 个任务如何构成

每个任务输入可写为 $x=(q,I,F)$：自然语言请求 $q$、可选的图像或视频参考 $I$，以及可选的规格文件 $F$。Agent 从初始 Blender 工作区 $s_0$ 出发，根据观察选择动作：

$$
a_t=\pi(x,o_{\leq t}),\qquad s_{t+1}=E_B(s_t,a_t).
$$

最终交付物 $A_T=(B,R,V,X)$ 包含可编辑 Blender 工程 $B$、渲染图 $R$、动画或视频 $V$，以及辅助文件 $X$。这一定义允许存在多种有效实现，只要求输出满足任务简报和参考材料。

数据集包含 **223 个任务**，分为 9 个主类别、22 个子类别和 16 种应用场景。其中 78 个是无图像或视频参考的文字任务，130 个使用图像加文字，15 个使用视频加文字。另有 59 个任务附带 Markdown、YAML 或 JSON 规格文件，用来规定尺寸、材质、相机或资源预算；规格文件可以与视觉参考同时出现。

[![BlenderWorld 的应用场景、参考与附件类型，以及 2,651 条准则的类别和权重分布](/blog/assets/blenderworld/dataset-statistics.webp)](/blog/assets/blenderworld/dataset-statistics.webp)

*图 2. 应用场景、参考与附件类型、准则类别和重要性权重。图中 11 个最大应用场景覆盖 223 个任务中的 213 个；不同参考与规格类型可以共存。图源：原技术报告 Figure 3。*

任务简报先经过结构检查，确认资源可访问、规格可解析且交付要求完整；再由不同于任务生成器的模型检查图文一致性、约束冲突和可执行性。准则由需求台账生成，经试评、至少两个独立模型复核和人工补充审查后冻结。这里的任务与准则仍然包含模型参与生成和编辑，并非全部由专业 3D 艺术家从零手工编写。

最终得到 **2,651 条二元准则**，每题 6–22 条，平均 11.9 条，覆盖功能、几何、构图、材质、灯光、空间布局、物理、尺度等 13 类。83.3% 的准则权重为 3，14.9% 为 2，1.8% 为 1；规格文件直接贡献了 500 条准则。

### 3.2 生成阶段：统一任务，不完全统一系统

Agent 可以通过 Blender Python API 与 MCP 工具执行代码、查询对象、查看视口、调用外部素材并反复修改。最终工作区被归档，生成容器与评测容器严格分离，冻结的准则不会暴露给生成 Agent。缺少 `.blend` 文件的任务直接记零，并保留在 223 题的分母中。

参考运行环境使用 Blender 4.2.10 LTS 和 Linux 单 GPU 容器。需要注意的是，GPT-6-Astra 与 GPT-5.6-Sol 使用 Codex，其余 11 个 Agent 使用 Claude Code；各模型还使用自身可用的最高推理强度。因此榜单比较的是“模型 + harness + 推理配置”的完整系统，并非严格控制接口后的单变量模型对照。

### 3.3 Automatic Agent Render：主动寻找可观察证据

评测首先检查并恢复提交物所需的依赖，然后由 Automatic Agent Render（AaR）根据任务、参考材料和准则选择八个互补视角。每个视角使用 Cycles 以 $1024\times1024$、64 samples 渲染，允许最多两次纠正性重渲染。

AaR 可以调整评测相机、取景和渲染设置，但不能修改提交物的几何、材质、灯光、动画或色彩管理，也不能替 Agent 修复缺陷。原始导出图片、视频采样帧和评测新渲染共同构成视觉证据；发生冲突时，原始导出物优先。

### 3.4 证据路由：看渲染，也查场景

2,651 条准则中，1,107 条（41.8%）路由给 VLM-as-Judge，通过渲染图、导出物和视频帧判断外观、布局与运动；1,544 条（58.2%）路由给 Agent-as-Judge，直接检查 `.blend`、对象属性和文件状态，验证尺寸、拓扑、内部结构、设置与交付要求。场景检查 Agent 必要时也可以参考视觉证据。

另一条质量通道由 VLM 对八个维度分别给出 1–10 的整数分：场景忠实度、物理合理性、风格与颜色、真实感、空间布局、比例与尺度、灯光与材质、完整性。

### 3.5 三个分数分别表示什么

若一题有 $m$ 条二元判断 $\hat y_j\in\{0,1\}$、权重 $w_j$，以及 $K=8$ 个质量评分 $d_k\in[1,10]$，则：

$$
S_{\mathrm{rubric}}=100\frac{\sum_{j=1}^{m}w_j\hat y_j}{\sum_{j=1}^{m}w_j},
\qquad
S_{\mathrm{dim}}=100\frac{\sum_{k=1}^{K}d_k}{10K}.
$$

主榜分数取两者等权平均：

$$
S_{\mathrm{fused}}=0.5S_{\mathrm{rubric}}+0.5S_{\mathrm{dim}}.
$$

最终 Score 是 223 题的宏观任务平均，失败保留为零。论文还报告 **Perfect**：一题所有二元准则全部通过才计为成功。它与高加权通过率并不等价，因为即使只漏掉一条低权重准则，也不再是 Perfect。

GPT-6-Astra 的总分比 Opus-5 高 6.9 分，文字任务为 78.6，多模态任务为 80.7；Opus-5 分别为 74.8 和 72.1。它的优势在多模态任务上更明显。

但 79.9 不能解释为“近八成任务完成”。GPT-6-Astra 只有 94/223 个任务通过全部准则，即 42.2%。它有 143 个任务达到至少 90 的加权准则分，其中 49 个仍漏掉至少一条要求。这个差距说明均值适合排序，Perfect 更能暴露生产验收中的长尾遗漏。

### 4.2 类别与资源：更长轨迹不自动带来更好工程

GPT-6-Astra 在 9 类任务中的 8 类领先，程序化与游戏资产最高，为 86.8；产品与制造为 83.9。唯一没有领先的是渲染与仿真：Opus-5 为 74.5，GPT-6-Astra 为 71.1。所有系统在程序化与游戏资产上的分数都高于艺术与动画、角色与动物，说明规则结构与制造物体相对容易，动态、自然形体和有机细节更困难。

资源使用也不存在简单的“越多越强”。Opus-5 平均 241K 输出 token、155 次工具调用，DeepSeek-V4.1-Flash 为 209K 和 168 次；GPT-6-Astra 为 84.5K 和 79.1 次，却获得最高分。另一方面，GPT-5.6-Sol 只用 39.9K token 和 44 次调用就取得第三名。由于模型、价格、harness 和推理配置没有完全控制，这些数字只能描述效率—质量组合，不能单独归因于规划能力或调用策略。

### 4.3 四类失败共同指向“二维正确、三维错误”

论文的定性审计归纳出四类反复出现的问题：

1. **缺失动态交互。** 场景中有要求的物体，却没有真正产生汇聚、轨迹、波纹等行为。
2. **视角不一致。** 人物由面向提交相机的单面照片卡片构成，从侧面观察就消失；改进贴图无法补上缺失的体积。
3. **细粒度几何畸变。** 狮子幼崽的眼睛过大、脚掌像手指，说明 Agent 没能检查并修复高频解剖细节。
4. **接触约束错误。** 强制透视任务中，Agent 把鞋尖与远处塔楼的投影误差压到 $1.19\times10^{-7}$，却让人物悬浮在草地上。局部二维约束被精确满足，基础三维支撑关系反而遗漏。

附录还给出一种更隐蔽的 **自检规格漂移**：任务要求 150 mm 木腿并带黄铜脚轮，Opus-5 在内部计划中把目标改成“木腿加脚轮总高 150 mm”，实际生成 102 mm 木材加 48 mm 脚轮；自检测到总高 150 mm 后错误通过。评测器重新测量木材本体，才发现比要求短 32%。这表明验证代码本身也可能忠实检查一个被 Agent 悄悄改写的目标。

### 4.4 自动裁判的可靠性与边界

主实验的自动渲染、准则判断和质量评分都使用 GPT-5.6-terra。作者用 150 对同任务输出进行人工偏好对比，每对由三名评审判断；剔除三方各投一个选项的 3 对后，剩 147 对。GPT-5.6-terra 的融合分数与多数人工偏好的严格一致率为 82.99%，Pearson、Spearman 和 Kendall 相关分别为 0.714、0.744 和 0.607。

当三个裁判的平均分差小于 10 时，70 个近分样本上的一致率降到 68.57%。而且这项验证测的是成对偏好，不是 2,651 条准则逐条事实正确率，也没有证明所有专业 3D 验收标准都被覆盖。论文也将专家校准、更精确的参数和几何检查、交互式操纵机构列为后续工作。

解读榜单还需要保留三点限制：第一，每个 Agent 每题只有一次运行，当前结果不包含重复试验方差；第二，Codex 与 Claude Code 两种 harness 和不同推理配置与模型身份绑定；第三，任务和准则的生成、编辑、评测都大量使用模型，尽管经过独立复核与部分人工审查，仍可能继承裁判偏好和覆盖盲区。

## 5. Conclusion

BlenderWorld 最重要的贡献，不只是增加了一张 3D Agent 排行榜，而是把评测单元从“最终看起来怎样”扩展为“工程内部到底建了什么”。八视角主动渲染、场景状态检查、任务级二元准则和整体质量评分共同减少了单视角视觉捷径，也让漏约束、伪三维、接触错误和自检漂移能够被分别定位。

实验显示，当前最强系统已经能完成相当复杂的 Blender 工作流，但高平均分与严格验收之间仍有明显距离：GPT-6-Astra 得到 79.9，却只有 42.2% 的任务通过全部准则。更频繁地观察或调用工具也不保证更好结果，瓶颈更像是把反馈转成正确的三维诊断与局部修复。

下一步值得把这种闭环拆得更细：让 Agent 在修改前显式记录原始规格和待验证假设；同时检查提交相机与反事实视角；将尺寸、接触、碰撞、骨骼和动画状态交给确定性脚本；最后用与生成阶段独立的验证器确认修复没有引入新错误。对于需要真正可编辑、可复用三维资产的任务，这些结构性验证比继续优化单张渲染的观感更关键。
