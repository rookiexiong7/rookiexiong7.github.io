作者：Xinge Peng、Zhen Fang、Ruibing Wang、Yongxuan Lv、Haodong Li、Guohui Zhang、Xiaoxiao Ma、Yiting Lu、Lin Chen、Zehui Chen、Feng Zhao  
**单位：** University of Science and Technology of China、The Chinese University of Hong Kong

## 1. Motivation：从搭出场景，到让场景真正工作

给定一张机械装置图片，Coding Agent 可以用 Blender 生成零件、设置材质，再输出一段动画。但程序顺利执行、画面与参考相似，仍不足以说明装置的机械关系正确：齿轮可能没有咬合，连杆的转轴可能错位，小球也可能在没有接触的情况下“触发”下一段运动。

ExeWorldBench 关心的是 **executable world modeling（可执行世界建模）**：模型能否理解世界的结构、约束和因果关系，并把这些理解落实为可执行的三维系统。这里的世界模型以代码和场景实现为载体，评价对象是生成的机械世界及其运行过程。

物理问答可以检查模型是否说得出运动规律，静态重建可以检查外观和几何，轨迹拟合可以检查运动是否相似。这篇论文尝试把这些要求结合起来，进一步追问：各个零件的运动能否组成连续、合理的机械因果链？

## 2. Insight：可运行、会运动与因果正确是不同要求

### 2.1 正确行为依赖结构，也依赖结构之间的连接

三维装配中的位置、朝向、接触面和转轴，都是运动能否发生的条件。模型即使正确实现一个跷跷板，也需要把它放在上游小球能够到达的位置，并使下游装置接收到足够且方向正确的作用。

为帮助理解，可以设想“小球沿斜坡滚下、碰倒多米诺骨牌、骨牌推动杠杆、杠杆释放第二颗球”的装置。每段都能播放动画，只说明局部有运动；完整系统还要求后段由前段的实际作用触发。这个例子说明了为什么多阶段组合需要独立评测。

### 2.2 减少输入指导，会增加不同类型的推理负担

看到单机构图片时，模型主要推断隐藏的运动和约束；看到多阶段装置时，还要恢复阶段之间的连接；只有文字目标时，则需要自己选择实现方案。ExeWorldBench 沿着这条路径增加任务的组合复杂度与设计自由度。

这种递进描述的是任务要求。不同任务集的构成、指标和难度分布并不相同，不能把跨任务分数直接当成同一批样本逐步撤去提示后的严格消融。

## 3. Method：三类任务与四个评价维度

### 3.1 T1：从静态结构推断完整机械运动

T1（Mechanism Executability）要求模型根据参考图片生成 Blender 程序，构建一个机械机构并执行完整运动。默认输入以单张静态图为主，完整运动参考用于评价；额外提供运动帧属于后面的实验设置。

数据来自公开的机械原理动画。作者筛除画质差、严重遮挡、组件边界不明确，以及机械活动组件少于三个的样本，再验证静态结构是否足以支持运动推断。

验证过程分四步：GPT-6 Astra 同时查看静态图和完整运动帧，提取三条静态可见的结构证据；Opus 5 只根据静态图和这些证据推断运动；Astra 将推断与参考运动对照；最后由五名人工标注者复核。证据被要求不能直接描述运动答案。

这是样本可推断性的筛选流程，不能把参与筛选时看到的完整运动帧误写成被测模型默认也能获得的信息。该流程支持数据可解性，但仍依赖模型筛选与人工判断。

### 3.2 T2：把机构接成 4–13 阶段的系统

T2（Compositional Executability）从原子机械组件库构造多阶段系统。GPT-6 Astra 生成包含 4–13 个阶段的组件顺序和预期交接关系，人工检查物理合理性，再由 Astra 与 Codex CLI 组合已有组件实现、调整空间布局，形成参考动画。

被测模型需要根据视觉参考实现整个系统。难点既包括每个机构如何运动，也包括组件距离、朝向与连接关系能否让运动持续传播。

附录 Table 5 统计了 15 类组件、850 次组件使用，其中斜坡占 30.12%，接球碗占 11.76%，多米诺骨牌链占 9.29%。**850 是组件出现次数，不是任务数量。** 这也提示了数据覆盖范围：结果主要反映这类机械组件及其组合上的能力，尚不能代表任意物理世界。

### 3.3 T3：从组件清单或高层目标设计世界

T3（Intent-Driven Executable World Synthesis）去掉直接视觉参考，分成两种设置：

| 设置 | 提供什么 | 模型需要决定什么 |
| --- | --- | --- |
| T3-1：组件约束合成 | 从组件库抽取的 4–12 个组件及其要求 | 组件顺序、空间布局、阶段间连接，使所有组件参与完整执行链 |
| T3-2：目标约束合成 | 目标、必要对象、状态与事件定义、初态、物理规则和依赖、终态 | 满足这些要求的具体机械实现 |

T3-1 先检查组件集合是否存在合理顺序和完整因果连接。T3-2 按 easy、medium、hard 生成任务，由 Opus 5 检查规范一致性、机械可行性和参考解可构造性，再经过人工复核。T3-2 虽然更加开放，输入仍有详细的对象与规则约束，不能理解为任意一句话生成完整世界。

### 3.4 评分同时覆盖外观、运动、交接和目标

论文使用 Opus 5.5 作为视觉语言模型评审器。代码运行成功率记为 $E$，另有四类内容指标：

| 指标 | 适用任务 | 含义与范围 |
| --- | --- | --- |
| Visual Structure，$V$ | 全部 | 几何、布局、机械装配和组件关系，惩罚穿插、断连等问题；0–10 分 |
| Mechanical Motion，$M$ | T1 | 对照参考运动，检查各组件的运动类型、方向、范围与时间变化；0–10 分 |
| Executable Causal Mechanism，ECM | T2、T3 | 将执行划成因果片段，检查组件行为与相邻阶段交接，再对片段评分取平均；0–10 分 |
| Goal Satisfaction，$G$ | T3-2 | 检查初态、过程、终态的各项条件是否完全满足，再汇总满足比例 |

对样本 $i$，令 $P_i^c$ 为类别 $c$ 中满足的条件数，$N_i^c$ 为条件总数，$c\in\{I,B,F\}$ 分别表示初态、过程和终态。总目标满足率为：

$$
G=\frac{1}{N}\sum_{i=1}^{N}
\frac{P_i^I+P_i^B+P_i^F}{N_i^I+N_i^B+N_i^F}.
$$

也就是说，先在每个任务内计算满足比例，再对任务取平均。每项条件是二元判定，但整个任务可以获得部分分数。因此，$G=90\%$ 不代表 90% 的任务全部成功，ECM 的平均分也不等于整条因果链的完整成功率。

### 3.5 修复前后与不同分母要分开读

主表采用 penalized 指标，把代码无法执行的样本也计入总体；附录另报 conditioned 指标，只在可执行样本上评分。下标 1、2 分别表示技术错误修复前后。

对于 API 生成结果，作者使用 GPT-6 Astra 与 Codex CLI 修复执行错误，要求保留原有场景结构和行为意图。这样可以观察修好实现错误后，还剩多少机械建模问题。修复后成绩属于原模型输出与外部修复器共同作用的结果，也不能当作原模型的一次生成能力。

## 4. Experiments：修好代码之后，机械能力还差多远？

### 4.1 运行成功率上升，因果评分仍可能接近零

原论文 Table 2 的 T2 结果摘录如下。$E_1\rightarrow E_2$ 是运行成功率的变化，$V_2$ 与 $\mathrm{ECM}_2$ 为修复后的全样本评分：

| 模型与执行方式 | $E_1\rightarrow E_2$ | $V_2$ | $\mathrm{ECM}_2$ |
| --- | ---: | ---: | ---: |
| GPT-6 Astra + Codex CLI | 99% → 99% | 5.33 | 5.25 |
| Claude Fable 5.1 + Claude Code | 100% → 100% | 4.45 | 4.08 |
| GPT-6 Astra，API | 81% → 91% | 3.86 | 2.47 |
| Claude Fable 5.1，API | 91% → 93% | 3.49 | 1.84 |
| DeepSeek-V4.1-Flash，API | 2% → 88% | 1.83 | 0.09 |
| Qwen3.8-Max，API | 9% → 62% | 1.21 | 0.00 |
| Kimi K3，API | 10% → 79% | 1.62 | 0.00 |

DeepSeek 的可执行率从 2% 升到 88%，ECM 却只有 0.09/10。即使只看修复后能够运行的样本，附录 Table 7 的对应 ECM 也只有 0.11。低分因此无法仅用“很多代码没跑起来”来解释。

T1 也存在结构与运动的差距：Astra + Codex CLI 的 $V/M$ 为 7.16/6.32，Fable 5.1 + Claude Code 为 6.44/5.68；API 版 Fable 修复后为 4.04/3.24。结构与运动评价相关，但外观和装配得分较高，并不保证运动同样正确。

### 4.2 执行框架有明显影响，但不是纯模型排名

在 T2 上，同为 Astra，Codex CLI 组合的 ECM 为 5.25，API 结果修复后为 2.47；Fable 的 Claude Code 组合为 4.08，API 修复后为 1.84。结果表明，完整 Agent 系统的实现方式会显著影响世界构建表现。

不过，带执行框架的 Agent 与 API 一次生成具有不同的工具和交互条件。论文没有在这些主表中给出统一的 token、时间和工具调用成本对照，因此不能将差异全部归因于基础模型的物理理解，也不能据此得出同成本效率排名。

### 4.3 给定目标后，选择机械实现仍然困难

下表汇总 Table 3、Table 4 中四组较强系统的修复后结果，均采用全样本口径：

| 模型与执行方式 | T3-1 ECM | T3-2 ECM | T3-2 Goal Satisfaction |
| --- | ---: | ---: | ---: |
| GPT-6 Astra + Codex CLI | 6.11 | 5.82 | 90.14% |
| Claude Fable 5.1 + Claude Code | 5.70 | 5.17 | 75.19% |
| GPT-6 Astra，API | 3.34 | 2.55 | 41.07% |
| Claude Fable 5.1，API | 2.75 | 1.85 | 31.31% |

这四组系统在目标约束合成中的 ECM 都低于组件约束合成，支持“自行选择实现机制会增加负担”的解释。但低分模型并非全部下降，例如 Kimi K3 从 0.40 到 0.63；不宜把论文概括的总体困难写成每个模型都单调退化。

论文还将目标满足拆成初态、过程和终态，发现 API 模型通常更容易满足初态要求。摆出合理的起始场景，并不意味着系统能够持续产生正确交互并抵达指定终态。Astra + Codex CLI 的 90.14% 条件满足率与 5.82/10 ECM 也提醒我们：两种指标衡量不同方面，较高的条件覆盖不能替代完整机制检查。

### 4.4 因果链变长，局部错误更难控制

[![按执行阶段数分组的 T2 与 T3-1 ECM，较长链条总体得分下降](/blog/assets/exeworldbench/horizon.webp)](/blog/assets/exeworldbench/horizon.webp)

*图 2. 修复后的结果按执行阶段数分组。左为 T2，右为 T3-1；横轴是机械执行阶段数，不是 Agent 推理轮数。图源：[原论文 Figure 2](https://arxiv.org/html/2610.15166v1#S4.F2)。*

T2 中，Fable + Claude Code 与 API 版 Astra 在 13 阶段时的 ECM 降至短链得分的大约五分之一，Astra + Codex CLI 的退化较小。T3-1 中，API 版 Astra 在 8 阶段时跌到 1.0 以下。

曲线总体随长度下降，但存在回升，并非每增加一个阶段都会严格降低分数。这里是按不同样本的链长分组，组件种类和任务难度也可能一起变化；实验支持长链更困难的趋势，尚未单独隔离链长的因果效应。

### 4.5 更多运动参考只有有限帮助

作者额外给模型提供参考视频中的运动帧。T1 中除 API 版 Astra 外，其他模型均有提升，但幅度通常有限；T2 中多数模型受益，GLM-5.3-Flash 和 API 版 Astra 略有下降。

这说明补充运动观测有时有效，但观察到轨迹之后，如何把它转成合理的三维结构和阶段连接，仍然是瓶颈。结果不能推出运动信息没有价值，也没有证明继续增加帧数一定能解决问题。

### 4.6 视觉因果评分的证据边界

论文希望评价真实机械作用，并通过 ECM 检查阶段交接。不过，其已描述的评估主要依据生成视频的采样帧、参考运动和任务规范，由 VLM 判断行为与条件是否满足。

从评估方法出发，仍需区分“画面呈现了合理的因果顺序”与“实现确实依赖对应的物理作用”。如果两个物体按预定时间先后运动，视频可能呈现出正确顺序；要进一步验证接触依赖，可以移走上游物体、改变初始位置或施加扰动，检查下游运动是否相应改变。这些属于后续可增加的测试，本文没有将其视为论文已完成的实验。

另外，Astra 参与了数据筛选、参考构建和技术修复，Opus 系列参与验证与评分。人工复核有助于检查数据质量，但尚不能替代对评审器可靠性、模型偏好及反事实一致性的独立验证。当前成绩应理解为该任务分布和评估协议下的结果。

## 5. Conclusion

ExeWorldBench 的贡献是把代码构建世界拆成可检查的不同要求：程序能否执行、结构是否合理、组件如何运动、阶段怎样交接，以及初态到终态的条件是否满足。实验中最明确的证据是，技术错误修复能大幅提高运行成功率，却无法同步修好机械关系与多阶段执行。

它也为后续研究提供了具体方向：除了改进空间装配和长链设计，还可以加入接触、约束与状态日志，进行受控扰动，并在统一资源预算下比较完整 Agent。这样才能进一步判断系统是否掌握了可复用的机械机制，以及这些机制能否在初始条件变化后继续工作。
