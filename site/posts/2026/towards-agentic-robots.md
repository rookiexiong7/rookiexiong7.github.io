## 1. Motivation：会开抽屉，不等于能可靠取出目标

考虑一个任务：“从抽屉里取出蓝色物体，放到桌面上。”一个已经训练好的机器人策略，可能能够完成抓住把手、拉开抽屉这段动作。但完整任务还要求系统判断：把手在哪里，抽屉是否真的打开，目标有没有被遮挡，抓取是否落空，以及下一项技能能否从当前姿态开始执行。

如果拉动失败，正确响应也不总是再试一次。机器人可能需要换视角确认把手、调整接近方向、换用另一项技能，或者承认现有执行器无法完成任务。任务结束后，这次经历还能用于修正成功标签、补充训练数据、改进技能程序，或者设计更有针对性的测试。

这些决策分布在不同位置：有的发生在模型内部，有的发生在数据管线，有的修改模拟环境，还有的属于运行时软件。仅按“用了哪个大模型”或“是不是 VLA”分类，很难解释完整系统为什么成功、为什么失败，以及下一步应该修改哪里。

这篇综述因此围绕四个问题组织文献：**Agent 应该学习和决定什么，应该获得什么数据，应该构建什么环境，以及应该怎样调用和改进机器人能力。** 对应的四个领域是 Model、Data、Environment 和 Harness。

## 2. Insight：沿着决策、执行、反馈与保留的改变分析系统

### 2.1 Agentic 的关键是如何组织和调整执行

原文将 Agentic Robots 定义为：围绕给定目标，利用环境观测和执行反馈，自主规划并协调任务执行的机器人系统。Agent 选择步骤、动作、技能或工具，监测进展，再决定继续、补充信息、修改计划或从失败中恢复。它既可以在真实机器人上运行，也可以在仿真中运行。

这一能力可以由一个集成模型实现，也可以由模型、策略、程序和工具共同实现。因此，模块数量、是否生成代码、是否调用外部 API，都不能单独决定一个系统是否具有论文所讨论的 agentic 能力；需要看这些机制是否实际参与目标导向的决策与反馈。

原文也明确承认，自主机器人研究早已包含规划、监测、学习和恢复。这里关注的是基础模型 Agent 如何参与并组织这些功能。“Agentic”不自动意味着更高的自主等级，也不意味着系统完全不依赖人工指导。

### 2.2 四种技术传统可以共存

论文回顾了从机器人策略到 Agentic Robots 的发展，但将它们视为相互重叠、可以组合的研究方向。

| 技术方向 | 主要提供的能力 | 在完整系统中的位置 |
| --- | --- | --- |
| 传统机器人策略 | 从示范或奖励中学习观测到动作的映射 | 提供可执行行为，场景表示可以基于图像或三维几何 |
| Vision-Language-Action Models（VLA） | 将视觉、语言预训练知识与机器人动作连接 | 可以承担通用动作执行，也可以包含记忆、推理和子目标预测 |
| World Models / World-Action Models（WAM） | 预测交互后果，或联合建模未来观测与动作 | 支持想象、规划、仿真式评估或动作生成 |
| Agentic Robots | 选择、协调和修订执行，并组织能力改进 | 决定何时使用上述能力、如何接收反馈，以及怎样保留经验 |

一个 Agent 可以把 VLA 当作工具，把世界模型当作候选行动的预测器，再用经典运动规划器执行部分运动。VLA 自身也可能包含高层推理。分类应当追踪具体决策及其作用，而不是把系统强行放进互斥的技术阵营。

### 2.3 当前任务变好，与持久能力变好，要分别验证

“机器人从经验中改进”可能指向至少三种过程：

| 改变发生在哪里 | 抽屉任务中的例子 | 需要验证什么 |
| --- | --- | --- |
| 当前回合的上下文或计划 | 发现把手被遮挡，换视角后重新抓取 | 新证据是否促成有效恢复 |
| 跨回合的记忆、技能或软件 | 保存接近策略，修订开抽屉程序 | 新任务能否复用，旧能力是否发生回归 |
| 模型参数 | 用筛选后的失败和恢复轨迹更新策略 | 训练后是否在独立任务上提高，是否遗忘已有能力 |

前一种不要求更新权重，后一种也不保证来自完全自主的数据生产。把改动对象、发生时机和验证范围说清楚，才能判断一项工作究竟展示了什么。

### 3.2 Model：把失败归到需要改变的决策上

Model 不只讨论模型架构，还讨论 Agent 怎样参与学习和使用模型。

**Training 作用于学习过程。** Agent 可以写奖励函数、修改训练配置、组织实验并根据 rollout 结果继续修订。奖励代码能运行，只能说明接口有效；训练出的机器人是否遵循任务意图，还需要检查实际行为。搜索范围从奖励扩展到整个训练程序之后，固定评价目标、保存实验记录和控制计算成本会更加重要。

**Perception、Planning 与 Robot Control 连接证据和动作。** 看见一个把手，不代表已经得到精度足够的抓取位姿；规划出“打开抽屉”，也不代表当前姿态和可用控制器能够执行。感知需要提供任务相关的对象、关系、几何或不确定性，规划需要检查依赖和可行性，控制接口则需要把意图落到执行器能够理解的表示上。

控制表示可以是语义动作、目标位姿、完整程序，也可以是运动约束和代价函数。接口越高层，越依赖底层执行器已经具备相应能力；接口越细，Agent 就越需要处理几何、反馈频率和调用开销。哪一种更合适，取决于任务和执行器。

**Adaptation 关注经验改变了什么。** 修改提示中的条件、调整规划器参数、训练高层决策模型、更新底层策略，具有不同的作用范围。若失败来自过期的把手坐标，新增观测可能比重训策略更直接；若在正确定位和合理计划下仍反复无法拉开抽屉，才更可能需要改进执行能力。

### 3.3 Data：采集、标注与筛选是不同决策

数据采集包含三种来源：真实机器人交互与人类示范、模拟器中执行得到的轨迹，以及生成模型合成的观测和运动。Agent 可以决定下一个采集任务，针对薄弱阶段补数据，或协调生成与验证工具。但持续采集还依赖场景复位、成功判断、失败重试和人工介入机制；“自动提出任务”不等于整条管线都能无人运行。

标注把经验转化为可学习的监督，包括任务文字、空间位置、接触或操作区域，以及中间进度和最终结果。这里需要追问标签的证据来源：模型判断、几何计算、模拟器记录和人工纠正，其可靠性及适用范围不同。生成一段流畅的解释，不足以证明动作真的成功。

筛选则决定保留什么、修订什么。一个最终失败的回合，可能包含正确接近、有效抓取或成功恢复的片段；整条丢弃会损失经验，整条保留又可能教会策略无效行为。如果后续发现成功判据有误，历史标签也需要重新检查。

这三类功能形成的关键联系是：**执行暴露薄弱环节，Agent 有针对性地补充经验，再用可信的监督决定哪些经验进入训练。** 数据量增加只是其中一个中间结果，最终仍要检验策略是否受益。

### 3.4 Environment：场景可运行、任务可完成、评价有效，分别检查

Reconstruction 关注机器人实际能够交互的世界。抽屉外观正确，还不够；关节方向、运动范围、支撑关系和接触属性都可能影响执行。复现一段已有运动，也无法单独证明场景会对新的动作作出正确响应。视觉相似性、仿真稳定性、交互可行性与真实物理一致性，需要分别判断。

Task Generation 指定目标、初始条件、约束、成功条件和课程。自动修复一个不可完成的任务时，修复可能同时降低难度或改变原始意图，因此需要检查目标有没有被悄悄改写。同样，在固定目标下找到新动作序列，主要是在生成解决方案或示范，不一定是在生成新任务。

Benchmarking 决定测量什么能力。同一个“抽屉取物”任务，如果直接提供真实物体位姿，主要困难可能是规划与执行；如果只提供相机图像，还需要解决识别、几何和遮挡。如果每一步都能查询官方成功信号，与只能从传感器推断完成的系统相比，反馈条件也不同。

Agent 还可以自动构建评测、生成扰动并发现弱点。但评价器变得更准确、测试变得更困难、机器人本身变得更强，是三个不同结果。课程和测试若持续追随当前模型的表现变化，还需要一组独立规定的任务来检验能力是否真正增长。

### 3.5 Harness：让一次调用成为可靠执行的一部分

Harness 在本文中指组织 Agent 执行的外围软件：提供上下文和可调用能力，管理交接、记忆、监测与恢复，并承载技能和服务。它的作用贯穿整个执行过程。

[![Harness 在任务、证据、执行器与机器人反馈之间组织调用，管理记忆、恢复、技能和分层控制](/blog/assets/towards-agentic-robots/harness.webp)](/blog/assets/towards-agentic-robots/harness.webp)

*图 3. Harness 的六类功能。图源：原综述 Figure 7。中间一行是任务执行与反馈路径，外围模块决定这条路径怎样被组织和复用。*

**Orchestration：选对技能之后，还要完成状态和时序交接。** 开抽屉策略结束时，机械臂可能仍握着把手，而取物策略要求夹爪空闲、处于另一个起始区域。两个技能分别可靠，串起来仍可能失败。系统可以先把状态调整到下一执行器的适用范围，也可以选择适合当前状态的执行器。调用协议还要说明合法参数、返回状态、成功条件，以及什么时候交回控制权。

**Memory：保留历史，也要判断历史是否仍然有效。** “蓝色物体刚才在抽屉左侧”可以解释早先的行动，却未必能指导当前抓取。抽屉移动或物体滚动之后，目标身份可能仍然有效，位姿却需要重估。记忆因此包含写入、更新和检索三个问题；完整保存日志不等于能正确使用记忆。

**Monitoring and Recovery：发现问题、选择响应、执行修复。** 执行前检查判断候选动作是否有效；执行中监测判断是否停滞或违反约束；执行后检查判断任务是否达到目标。随后还需要选择重试、重新定位、换执行器、重规划或复位。发出停止请求后，应先确认机器人已进入可继续决策的状态；从失败现场恢复与复位后重新尝试，也应分开统计。

**Skills：让经验变成可重复使用的做法。** 技能既可以是加载到上下文中的操作说明，也可以是能够调用的程序。记忆记录“发生了什么”，技能提炼“遇到这种情况怎样做”。新技能或修订版本需要验证、回归检查和必要的淘汰机制。一次成功不能说明它适用于所有场景；修改技能文档或代码，也不等于模型权重已经更新。

**Infrastructure：工具和服务决定能力边界。** 感知、深度估计、抓取生成、运动规划及策略推理，可能运行在不同设备和服务上。接口决定 Agent 能请求什么、获得什么错误反馈，也决定哪些动作在到达硬件前会被拦截。一个只返回 `success` 的工具，很难帮助模型区分“请求被接受”“动作执行完毕”和“物体确实被拿起”。

**Layered Systems：不同决策以不同频率运行。** 论文用 System 2 指代任务规划器，用 System 1 指代学习得到的视觉运动策略，用 System 0 指代运动规划、逆运动学等解析控制。这里的 System 0 是本文采用的术语，不应视为全领域统一定义。分层要解决的是上下层交换什么、多久交换一次、谁有权中断，以及慢层的旧指令何时失效。

高层每次都重新推理会增加延迟，长时间不接收反馈又可能错过失败。事件触发和轻量进度监测提供了一种折中：常规运动继续交给执行器，遇到停滞、目标变化或证据不足时，再调用较慢的规划模型。

### 3.6 把四个领域连成执行与改进的过程

沿着抽屉任务，可以这样理解它们的联系：Model 解释目标并提出下一步；Harness 检查调用、调度执行器并接收结果；Environment 提供交互条件与评价依据；Data 保存并整理经验。当失败反复出现时，改动可能落在不同地方：补充感知数据、修订技能、调整训练流程，或者修复不合理的模拟场景。

这个过程并不要求每次失败都触发所有领域一起修改。恰恰相反，分类的价值是帮助定位问题，让改动与证据对应。例如，改进场景关节定义后任务成功，证明的是环境修复；在固定环境与评价器下，更新后的策略表现更好，才支持模型能力提高。

## 4. Experiments：怎样判断 Agent 的实际贡献？

### 4.1 综述提供文献分析，没有统一重跑的总榜

原综述没有提出一个新控制模型并对所有方法统一重跑。其比较表主要整理方法的输入、输出、执行器、反馈、记忆形式、检查时机和更新方式。正文中的成功率、延迟和提升幅度来自各项被引工作，不能拼成一个条件一致的性能排名。

为具体说明论文讨论的评价问题，下面回查两项代表性工作的原始实验。两者分别说明冻结执行模型后的系统收益，以及同一系统内规划和恢复模块的作用，不作跨论文排名。

### 4.2 Harness VLA：冻结动作模型后，外围组织仍然能改变结果

Harness VLA 将冻结的 VLA 包装成 `vla_act` 原语，同时提供移动、旋转、夹爪等解析动作。规划者根据当前观测组织这些原语，在适当阶段调用 VLA。下面采用其 **arXiv v5，2026 年 9 月 24 日**的 Table 2、Table 3。

标准 LIBERO 包含四个任务套件，各评估 10 个任务、每任务 10 个种子，共 400 次。LIBERO-Pro 在四个套件上分别加入指令重定向和位置交换，共八个评估单元，每单元 100 次，共 800 次。

| 设置 | 直接运行冻结的 π_RLinf | Harness VLA（CC） | 差值 |
| --- | ---: | ---: | ---: |
| 标准 LIBERO | 95.3% | 96.0% | +0.7 个百分点 |
| LIBERO-Pro | 50.0% | 82.4% | +32.4 个百分点 |

π_RLinf 是 RLinf 发布的 `pi05_libero130_fullshot` π0.5-SFT 检查点，两种条件使用相同的 VLA；CC 表示论文的 Claude Code 规划者配置。Harness 行使用任务级探索建立的记忆，属于 **few-shot memory 设置**，不能写成零样本成绩。

标准任务上的差距很小，扰动任务上的差距明显扩大，说明目标重定位、执行前准备和原语组合在这些条件下有实际价值。但这个实验固定的是 VLA 检查点；外围系统增加了规划者、记忆、解析动作与反馈处理，尚不能把全部增益归因于某一个模块，也不能据此推出相同计算成本下的优势。

版本中的零样本对照进一步说明了记忆条件的重要性：在 LIBERO-Pro Goal 的位置交换设置中，CC 从有探索记忆时的 87.0% 降到不检索对应任务记忆和全局记忆时的 31.0%。这些是同一子集的结果，不应拿来与全套件 82.4% 混用。模型是否提前获得过可复用策略，直接影响对“在线推理能力”的解释。

### 4.3 Show-Harness：规划和恢复需要通过同系统消融来判断

Show-Harness 将平移、旋转、抓取和释放表达为语义动作，再由本体专用解释器落实到机器人运动。其 **arXiv v1，2026 年 9 月 9 日**在真实 Franka 机械臂上，以 Gemini-3.1 Pro 为零样本决策模型，进行了插件消融。

原文 Section 5.4.3 / Figure 9 的默认插件实验使用五个放盘任务，按默认协议每任务 10 次。下表只摘录这个子集中的三个条件。

| 同一系统的配置 | 成功率 |
| --- | ---: |
| 默认配置 | 96% |
| 移除子任务规划 | 60% |
| 移除失败恢复 | 72% |

移除规划后，机器人更容易直接拖动物体，而没有形成抬起、运输、放置的合理阶段；移除恢复后，空抓未被及时处理，后续动作可能继续围绕一次不存在的成功抓取展开。这些结果使“规划”和“恢复”的作用落到了可观察的失败模式上。

它们仍是有限操作任务上的证据，而且单项移除的影响不能简单相加。该论文还有十任务主表、专门的隐藏物体场景和不同训练条件，不能把这里的 96% 当作全部任务的总体成绩。与仿真的 Harness VLA 相比，这组实验的机器人、任务、动作接口和反馈条件都不同。

### 4.4 从综述提炼一套可执行的评价问题

原文主张同时保留受控比较和端到端评价：固定条件能帮助识别模块贡献，自由组合工具则能测量完整系统的能力。根据这一主张，可以把后续实验问题整理如下；这是本文的评价建议，不是综述已经完成的实验。

| 要回答的问题 | 需要控制或报告的条件 | 不能只看什么 |
| --- | --- | --- |
| 规划和调度是否有效 | 相同执行器、观测权限、工具集合与交互预算 | 最终成功率一个数字 |
| 记忆是否提供有效信息 | 记忆来源、是否经过目标任务探索、场景变化后是否刷新 | 上下文长度或存储量 |
| 恢复是否真正解决失败 | 扰动方式、失败现场状态、是否允许复位、重试次数 | 重试后的最好一次结果 |
| 技能或模型是否持续改进 | 独立测试、旧任务回归、评价器是否固定、人工介入 | 被接受的修改数量 |
| 系统是否更高效 | 推理、通信、工具、机器人运动与重试的完整时间和成本 | 单次模型推理延迟 |
| 是否能够适配新本体 | 新机器人是否见过、额外配置、标定与训练量 | 使用相同动作名称 |

特别是自我改进系统，候选修改的产生者与最终判断依据需要有清楚的边界。如果 Agent 同时修改任务、奖励和成功判据，得分提高可能来自目标改变。独立评价和旧能力回归检查，才能帮助区分有效进步与测量方式的变化。

## 5. Conclusion

这篇综述的主要价值，是把机器人 Agent 的研究对象扩展到完整的执行与能力开发过程。Model 决定怎样理解、学习和行动；Data 决定哪些经验被获得并转化为监督；Environment 决定在哪些世界和任务上练习、如何测量；Harness 则组织可调用能力、记忆、交接与恢复。

它提出的四个后续方向也与这些边界对应：公平评价要分清模型、执行器和接口的贡献；真实部署要处理不确定观测与实际动作状态；高效运行要权衡推理时机和完整执行成本；跨本体泛化要让计划适应新机器人的能力与约束。这些都是待解决的问题，分类框架本身并没有证明它们已经实现。

一个值得进一步研究的切口，是固定执行器和时间预算，主动改变物体位置或技能起始条件，比较系统能否识别过期证据、补充必要观测并正确交接控制权。再将经过验证的恢复经验用于后续任务，检查收益能否保留、旧能力是否退化。这样的实验可以把“更会推理”和“更可靠地完成物理任务”之间的关系测得更清楚。
